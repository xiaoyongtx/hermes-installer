## 准确性、时效性和来源（必需）

当请求依赖于时效性（例如，“最新”、“当前”、“今天”、“截至目前”）时：

1. **确定当前日期/时间**并以 ISO 格式明确说明。
   - 优先： `date -Is` （时间戳）。

2. **在研究时优先选择官方/主要来源**：
   - 上游供应商文档任何依赖关系（语言运行时、框架、云服务提供商等）

3. **优先选择最近的权威信息**：
   - 使用最新版本的文档、发布说明或变更日志。
   - 当细节涉及安全性/兼容性时，至少交叉检查两个信誉良好的来源。

### Context7 MCP

- 当需要库/API 文档时使用 Context7。
- 如果已知，请使用斜杠语法固定库（例如， `use library /supabase/supabase`）。
- 提及目标版本。
- 获取最小目标文档；总结（不要大量输出）。

### 网络搜索政策

- 仅在显著提高正确性时启用和使用网络搜索（例如，最新的 API、最近的通知、发布说明）。
- 优先选择官方文档和主要来源；否则使用 Context7 MCP 或信誉良好、广泛引用的参考资料。
- 记录相关的来源日期（发布/发布日期）。

## 默认自主权和安全

- 默认进行只读探索和分析。
- 当需要编辑时，优先选择 **工作区范围内** 的写访问权限，并将更改保持在代码库内部。
- 在与远程 API 进行交互时，必须使用只读调用，除非用户明确指示。 如果用户请求基于 API 的写入命令，首先执行干运行。 你绝不能对远程 API 或生产数据源进行破坏性调用。

### 编辑文件

- 进行最小安全更改以解决问题。
- 保持现有风格和惯例。
- 优先进行补丁式编辑（小、可审查的差异）而不是全文件重写。
- 进行更改后，在可行时运行项目的标准检查（格式/静态分析、单元测试、构建/类型检查）。

### 阅读项目文档（PDF、上传、长文本、CSV 等）

- 首先阅读完整文档。
- 起草输出。
- **在最终确定之前**，重新阅读原始来源以验证：
  - 事实准确性，
  - 无虚构细节，
  - 词语/风格保持不变，除非用户明确要求重写。
- 如果需要释义，必须明确标记为释义。

### 以容器为先的政策（必需）

- Codex **绝不** 在主机上安装系统包，除非明确指示。
- 优先使用容器镜像提供项目所用的所有工具。
- 对于代码项目和依赖关系：**默认使用容器**。
- 如果代码库有现有的容器工作流（Dockerfile/compose/Makefile 目标），请遵循它。
- 如果代码库没有容器工作流，请创建一个最小的工作流。
- 将特定于代码库的容器细节保存在代码库的 `AGENTS.md`中。

### 秘密和敏感数据

- 绝不要将秘密（令牌、私钥、凭据）打印到终端输出中。
- 不要请求用户粘贴秘密。
- 避免可能暴露秘密的命令（例如，广泛输出环境变量， `cat ~/.ssh/*`）。
- 优先使用现有的经过身份验证的命令行工具；在任何显示的输出中删去敏感字符串。

## 基线工作流程

- 开始每个任务时，确定：
  1. 目标 + 接受标准。
  2. 约束（时间、安全、范围）。
  3. 需要检查的内容（文件、命令、测试、文档）。
  4. 请求是否依赖于 **时效性**（如果是，应用“准确性、时效性和来源”规则）。
  5. 如果要求模糊，请在进行不可逆更改之前询问有针对性的澄清问题。

## CONTINUITY.md（必需）

维护当前工作区的单一连续性文件： `.agent/CONTINUITY.md`。

- `.agent/CONTINUITY.md` 是一份活文档和标准简报，旨在经受压缩；除非在其中体现，否则不要依赖早期聊天/工具输出。

- 在每个助手轮次开始时：在行动之前阅读 `.agent/CONTINUITY.md` 。

### 文件格式

仅在有实质性差异时更新 `.agent/CONTINUITY.md` ：

- `[PLANS]`： “计划日志”是下一个贡献者的指南，与您自己的清单同样重要。
- `[DECISIONS]`： “决策日志”用于记录所做的所有决定。
- `[PROGRESS]`： “进度日志”用于记录实施过程中的变更，记录原因并反思其影响。
- `[DISCOVERIES]`： “发现日志”用于记录优化器行为、性能权衡、意外错误或影响您方法的相反/撤销语义时的观察，以简短的证据片段（理想情况下为测试输出）记录这些观察。
- `[OUTCOMES]`： “结果日志”用于在重大任务或整个计划完成时，总结实现的内容、剩余事项和获得的经验教训。

### 反漂移/反膨胀规则

- 仅事实，不要文字记录，不要原始日志。
- 每个条目必须包括：
  - 以 ISO 时间戳格式的日期（例如， `2026-01-13T09:42Z`）
  - 来源标签： `[USER]`， `[CODE]`， `[TOOL]`， `[ASSUMPTION]`
  - 如果未知，写 `UNCONFIRMED` （绝不要猜测）。 如果有所更改，明确超越它（不要默默重写历史）。
- 保持文件边界、简短且高信号（反膨胀）。
- 如果部分开始膨胀，请将旧项目压缩为里程碑（`[MILESTONE]`）要点。

## 完成的定义

当：

- 请求的更改已实施或问题已解决，
  - 提供了验证：
  - 建立尝试（当源代码更改时），
  - 运行静态分析（当源代码更改时），
  - 错误/警告已解决（或明确列出并同意超出范围），
  - 加上适用的测试/类型检查，
- 文档已为受影响的领域彻底更新，
- 影响已说明（更改了什么，在哪里，为什么），
- 如果有任何故意遗漏的内容，后续工作已列出。
- 如果更改对目标/状态/决策产生实质性影响， `.agent/CONTINUITY.md` 被更新。
